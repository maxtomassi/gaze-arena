# Gaze Arena — instructions for Claude Code

Open-source web games for children who use an eye tracker with dwell-click.
The device turns gaze into ordinary left mouse clicks: the games do NOT handle eye tracking.
Themes: football (soccer), wrestling, lots of action. All the fun comes from feedback, never from speed.

Stack: Phaser 4 + TypeScript + Vite. Audio: Howler.js. Tests: Vitest + Playwright. No backend.
Logical resolution 1920×1080, `Phaser.Scale.FIT`, centered.

## Repository structure (npm workspaces monorepo)
```
packages/kit/             shared library (@gaze-arena/kit): GazeButton, InputGate, Settings, AudioBus, i18n,
                          start screen, adult panel, simulator mode, theme, common strings and sounds
games/<game-id>/          one self-contained Vite app per game, independently buildable and deployable
  SPEC.md                 the game's spec and acceptance criteria
  src/                    scenes and game logic
  src/i18n/<locale>.json  game-specific strings
  public/assets/          game-specific images and audio (audio/<locale>/ for voice lines)
  tests/                  unit and e2e tests for this game
  vite.config.ts          base: './' so the build works under any URL path
  assets.yaml             manifest of generated images for this game (see Asset pipeline)
templates/game/           skeleton copied by `npm run new-game <game-id>`
tools/asset-gen/          script that generates, post-processes and records images from assets.yaml
apps/hub/                 optional launcher page linking to deployed games (later)
docs/                     design principles and contributor docs
```

## Independence rules
- A game may import only from `@gaze-arena/kit` and its own folder. Never import from another game.
- The kit never imports from games and contains no game-specific logic or assets.
- `npm run build -w games/<game-id>` must produce a fully static, self-contained `dist/`
  (kit bundled in, fonts and assets local, no CDN, relative paths) that runs from any host or subpath.
- Each game is its own PWA with its own manifest and service worker.
- Settings are stored in `localStorage` under a shared key prefix (`gaze-arena:`) so games served
  from the same origin share them; games on different origins simply have their own.
- Changes to the kit must keep every existing game building and passing tests.

## Language
- All code, identifiers, comments, tests, docs and commit messages are in English.
- Player-facing text is localized. Supported locales: `en`, `it`. Never hard-code a user-visible string.
- Common strings live in `packages/kit/src/i18n/<locale>.json`, game strings in `games/<id>/src/i18n/<locale>.json`;
  the kit merges them. Access text only through `t('key')`; game keys are prefixed with the game id.
- Every key must exist in every locale (a test enforces this in the kit and in each game). Add keys to `en` first.
- Locale-specific audio falls back to `en`, then to a generic sound.

## Golden rules (non-negotiable)
- NEVER timers that affect the outcome, NEVER reaction windows, NEVER game over for inactivity.
- Every clickable element MUST be a `GazeButton` from the kit. No direct `setInteractive` in scenes.
- Hitboxes ≥ 340×340 logical px by default, scaled by `settings.targetScale` (0.8–1.5). Hitbox = graphic + 18%.
- No targets with y < 108 or y > 990 (dead zones). A scene's rest area is never clickable.
- Single left click only (`pointerup`): no hover-to-activate, double click, drag or right click.
- Every action: `InputGate.lock()` for the whole animation + 500 ms; a button re-arms only on `pointerout`.
- Debounce: repeated clicks within 400 ms at the same spot are ignored.
- Full-screen flashes ≤ 3 per second; respect `settings.intensity` ("calm" | "normal" | "max").
- Adult menu only from the keyboard (Esc or P), never reachable by gaze.
- No real brands, leagues, wrestlers, logos or copyrighted music.

## Art and assets
- Characters, UI elements and effects are drawn in code: SVG parts (head, torso, arms, legs, props)
  assembled and animated in Phaser. Shared characters and parts live in `packages/kit/src/art/`.
  Never use raster images for anything that must animate.
- Style: thick black outlines (6 px at 1920×1080), flat saturated fills from the "Arena Night" palette,
  big-head proportions. Costumes and team colors are parameters, not separate drawings.
- Backgrounds and static illustrations are generated by `tools/asset-gen` from each game's `assets.yaml`
  (full rules in `docs/asset-pipeline.md`). Generated files are committed; never generate during build, dev or tests.
- Never call image or audio generation APIs yourself and never hard-code API keys; I run `npm run assets` manually.
- Sounds: CC0 packs first; generated voice lines follow the same manifest approach, per locale.

## Commands (from the repo root)
- `npm run dev -w games/<id>` · `npm run build -w games/<id>` · `npm run build` (all)
- `npm test` · `npm run e2e` · `npm run typecheck` · `npm run lint` (all workspaces)
- `npm run new-game <game-id>`
- `npm run assets -w games/<id>` (generate missing images; needs an API key in `.env`, run by a human)
- After every change: `npm run typecheck && npm test`.

## Workflow
- One game at a time. Before working on a game read `docs/design-principles.md` and `games/<id>/SPEC.md`.
- Explore → propose a plan → wait for my approval → implement → test → screenshots with Playwright MCP.
- Don't add dependencies without asking. Only use assets with a license compatible with redistribution
  (CC0 preferred) and record each one in the game's `ASSETS.md` (kit assets in `packages/kit/ASSETS.md`).
